# Tier 4 Live Attendee Consumption Gauntlet — Final User Outcome Gate

## End-User Outcome Spine

The promised outcome is not only that the provider ladder can be provisioned. The promised outcome is that a real attendee can enter the live event, consume the controlled live stream through the attendee-facing path, and remain protected from backend/provider details while owner/showrunner/crew can control live access.

## Required proof

The Tier 4 attendee live-consumption gauntlet must generate evidence during the run and prove:

1. A newly scoped Tier 4 event is active.
2. Controlled RTMP media has been pushed into the primary StreamYard-compatible RTMP into LiveKit path.
3. The attendee session is created through an authorized Tier 4 setup lane.
4. The attendee browser reaches the branded live stage surface.
5. The attendee can consume the controlled live stream by receiving a live attendee token while permitted.
6. No provider secrets are visible to the attendee, including RTMP URLs, stream keys, LiveKit secrets, Daily keys, Zoom secrets, Cloudflare tokens, bearer tokens, or backend diagnostics.
7. Owner/showrunner/crew can permit / revoke / re-permit live-event access.
8. Revoked attendees lose live token access.
9. Re-permitted attendees recover live token access.
10. Backend logs record permit, revoke, re-permit, and Tier 4 attendee-session creation events.
11. The proof is generated by the test itself and cannot be replaced by pre-existing evidence inspection.

## StreamYard limitation

StreamYard remains the primary production source, but StreamYard API automation is not claimed because StreamYard API access is enterprise-plan gated. The automated proof for this repo is the StreamYard-compatible Custom RTMP path: controlled broadcaster → LiveKit ingress → attendee live token/stage consumption.

## Hard fail

Tier 4 must fail if provider proof passes but attendee live consumption is unproven.


Contract tokens: backend logs; no provider secrets.
